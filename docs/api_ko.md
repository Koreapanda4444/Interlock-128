# 공개 API 계약

공개 헤더는 `include/interlock.h` 하나입니다. OpenSSL 타입과 컨텍스트의 내부 필드는 노출하지 않습니다. 키는 32바이트, 블록은 16바이트입니다.

`interlock_key_ctx *ctx = NULL;`로 초기화한 뒤 `interlock_key_ctx_create(&ctx, key, 32)`를 호출합니다. 성공한 컨텍스트는 확장키 112워드를 소유합니다. 원본 키를 수정하거나 소거해도 준비된 일정은 변하지 않습니다. 호출자는 자신의 원본 키를 소거할 책임이 있습니다.

생성 실패는 `ctx` 슬롯을 변경하지 않습니다. 기존 비NULL 슬롯을 덮어쓰지 않습니다. 슬롯과 키 입력의 범위가 겹치면 거부합니다. 비NULL 포인터는 선언한 길이의 유효 객체를 가리켜야 합니다.

컨텍스트는 생성 후 불변이며 전역 가변 scratch가 없습니다. 읽기 전용 재사용 시 서로 겹치지 않는 입출력을 사용하고, 실행 중 해제와의 동기화는 호출자가 담당합니다. 동시성 실험 자체는 후속 16번 범위입니다.

`interlock_key_ctx_free(NULL)`은 아무 작업도 하지 않습니다. 정상 컨텍스트는 소유한 일정을 `OPENSSL_cleanse`로 소거한 후 해제합니다. 호출자는 해제 뒤 포인터를 NULL로 바꾸어야 합니다. 해제 후 사용, 이중 해제, 초기화하지 않은 포인터는 지원하지 않습니다. 소거는 레지스터·운영체제 사본·덤프까지 없앤다는 보장이 아닙니다.

현재 11번까지는 생성·해제가 구현되어 있습니다. 전체 28라운드 암호화·복호화는 각각 12·13번에서 추가합니다. 독립 Python oracle, 전체 prefix 비교, sanitizer, 외부 소비자, 코드 경로 감사와 연구·성능 검증은 이후 계획입니다.
