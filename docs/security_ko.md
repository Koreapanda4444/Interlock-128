# Interlock-128 제한 분석 결과와 미해결 항목

현재 판정은 **연구용 실험 암호의 구현·제한 분석 기준선**입니다. `128`은 블록 폭입니다. 구현 일치와 아래 실험의 완료를 실제 기밀 보호의 승인이나 128비트 보안 강도 판정으로 해석할 근거는 없습니다. 제품 수식·256비트 키·28라운드·키 확장 도메인과 고정 벡터는 유지했습니다.

## 공격 모델과 확인한 결과

| 범위 | 모델·결과 | 재현 규모 | 해석 |
| --- | --- | --- | --- |
| 1R | 알려진 평문/암호문으로 첫 라운드 확장키 k0·k3 복구 | 1,024키, 키마다 서로 다른 평문 2개 | 복구량 64비트. 두 번째 평문에서 FS 관계와 실제 확장키를 확인. 마스터키 복구는 수행하지 않음 |
| 2R | 선택 평문 차분 LE32 `(1,0,0,0)`에 출력 첫 워드 차분이 네 값에 속함 | 128키×128쌍, 반례 0 | 사양 S-box 차분 집합과 회전·L32 선형성의 정확 계산 및 C 표본 검증 |
| 3R | 같은 입력차분에서 출력 두 번째 워드의 `0x001f001f` 10비트가 0 | 128키×128쌍, 반례 0 | FS 경로의 니블 지지집합 상계를 계산하고 C로 검증 |
| 부품 | DDT 최대4/16, Walsh LAT 최대절댓값8/16, 차수2·3·3·3, L32 rank32 | 16입력 전수, 32기저 역행렬 항등 | 부품의 정확 성질. 전체 라운드 trail/hull 경계를 계산한 결과는 아님 |
| 4·8·16·28R | 단일 입력비트/출력비트 discovery와 독립 holdout | 아래 등록 범위 | 제한된 편향 스크리닝. 전체 공격군·모든 키/차분에 대한 조사로 확대 해석하지 않음 |

실험의 C 드라이버에는 피해자 역할을 하는 고정 키를 설정합니다. 1R 복구식 자체는 평문/암호문만 사용하며, 키를 읽는 부분은 복구값의 ground truth 확인입니다. 2R/3R 분석도 설정한 키를 공격 계산의 입력으로 사용하지 않습니다. 실제 제품 공개 API는 전체 28라운드만 제공하며 축소 라운드 도구는 별도 빌드입니다.

2R 정확 집합은 `04004801, 6c001800, 94006801, fc003800`입니다. 이상적인 128비트 랜덤 순열의 서로 다른 출력 두 개가 이 조건을 만족할 단일 쌍 확률은 `4*2^96/(2^128-1)`입니다. 3R 조건의 단일 쌍 확률은 `(2^118-1)/(2^128-1)`입니다. 이 값에서 관측 쌍들의 독립성이나 결합 p-value를 가정하지 않습니다. 축소 라운드 성질로 `28-3` 같은 보안 여유를 산출하지 않습니다.

## 사전 고정한 스크리닝과 holdout

seed는 20261109입니다. discovery는 키 index0에서 각 라운드마다 입력 단일비트128개×1,024쌍, 출력128비트의 횟수를 계산했습니다. 라운드별 16,384개 비교 중 `abs(2*count-N)` 최대 하나를 고르고 동률은 입력비트·출력비트 오름차순으로 결정했습니다. 전체 discovery는 512조건·524,288쌍입니다.

후보를 고정한 뒤 키 index1~4와 별도의 holdout label·새 평문으로 후보당 각 키32,768쌍을 확인했습니다. 총16개 cohort·524,288쌍입니다. 키는 discovery와 다르고 결과를 본 뒤 후보를 다시 고르지 않았습니다. 원시 계수·등록·소스·실행파일 해시가 다르면 캐시를 거부합니다.

| 라운드 | 입력비트 → 출력비트 | discovery 횟수/1,024 | holdout 합산 횟수/131,072 | 합산 반전률 |
| ---: | --- | ---: | ---: | ---: |
| 4 | 19 → 47 | 451 | 65,299 | 49.819183% |
| 8 | 34 → 54 | 451 | 65,313 | 49.829865% |
| 16 | 120 → 40 | 438 | 65,717 | 50.138092% |
| 28 | 102 → 31 | 576 | 65,453 | 49.936676% |

합산 비율은 이 네 키의 기술통계입니다. 각 키의 횟수·비율·Wilson95% 구간은 [holdout-full.json](../research/results/holdout-full.json)에 별도로 남겼습니다. 4R/key index4의 개별 구간 `[0.488148625, 0.498974466]`은 0.5를 포함하지 않습니다. 이 관측도 그대로 기록하며, 16개 개별 구간의 가족 단위 유의성 판정이나 새 표본 확증을 수행한 결과로 부르지 않습니다. 28R 후보는 네 키의 개별 구간 모두 0.5를 포함하지만 미검출을 안전성 증명으로 해석하지 않습니다.

구간은 [NIST의 Wilson score 공식](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 사용하는 명목95%의 개별 Bernoulli 참고 구간입니다. 고정 생성 표본에 대한 기술통계이며 전체 키 모집단의 보안 강도 구간이 아닙니다. 16개 구간의 동시95% 보장을 주장하지 않습니다. discovery의 선택 후 p-value를 새 증거로 쓰거나 holdout에서 편리한 후보/키만 골라 보고하지 않았습니다. 별도 가족 단위 검정·다중 비교 보정은 수행하지 않았습니다.

## 완료 범위와 실행 예산

`research-full`은 harness, recovery, constraints, components, discovery, holdout의 여섯 구현 단계를 실행합니다. 기본 상한은1,200초이며 자동 연장하지 않습니다. 최종 Linux x86_64 GCC14.2 Release 실행은 약41.06초에 여섯 단계 `complete`로 종료했습니다. 이 실행시간은 성능 벤치마크 수치가 아닙니다. [전체 기준선](../research/results/full-baseline.json)에는 실제 source/binary hash, compiler·flags·Python/OpenSSL, seed·사례·진행 상태가 있습니다.

smoke는 기본120초 상한의 작은 사례로 CI에서 실행합니다. 코드/프로토콜/정확 invariant 정합성을 검사하고 편향 수치의 크기로 CI 합격 여부를 결정하지 않습니다. 별도0.3초 예산 검사에서는 discovery 5조건·5,120쌍을 보존한 채 `incomplete`로 종료했습니다. [시간초과 checkpoint](../research/results/timeout-checkpoint.json)는 제어 경로 검증이며 완료된 공격 실험과 구분합니다.

구현의 KAT·1,024개 전체 prefix 대조·메모리 계약·동시성·sanitizer·설치 소비자 검사는 [validation_ko.md](validation_ko.md), [sanitizers_ko.md](sanitizers_ko.md)에 있습니다. 로컬 LSan은 ptrace 제약으로 실행되지 않았고 ASan·UBSan은 누수 검사를 제외해 실행했습니다. Linux GCC/Clang CI는 `detect_leaks=1`로 별도 검증합니다. [소스·기계어 검토](implementation_audit_ko.md)는 대표 GCC 산출물의 제한된 검토이며 compiler spill·모든 stack/register 사본 소거나 전체 플랫폼의 constant-time 보장을 제공하지 않습니다.

## 미해결 연구

- 단일비트 차분을 넘어선 다중비트/워드 차분, truncated differential, trail·hull 및 라운드별 확률의 엄밀한 경계.
- MITM, boomerang, 관련키·다중키, 대수 공격과 다른 공격 모델. SHAKE 기반 키 확장과 전체 구조를 함께 다루는 보안 환원.
- 개별 키에서 관측한 작은 편향의 원인과 새 seed·키군·미리 정한 검정/예산을 사용하는 독립 재실험.
- 다른 컴파일러·CPU·provider의 기계어와 실제 부채널. 현재 기능/메모리 검사의 성공과 별도로 검토할 범위.
- native 비용·AES 참고값·호환 최적화 평가와 clean-checkout 최종 인수. 계획27~32번 후속 범위.

이번 결과는 성공한 축소 라운드 공격과 재현 가능한 제한 실험을 제공합니다. 전체28라운드 키 복구나 실질적인 전라운드 공격을 확립하지 않았으며, 안전성 인증·실사용 승인·검증되지 않은 경쟁 암호 대비 우위를 주장하지 않습니다. 새로운 전라운드 결함이 나오면 판정과 공개 설명을 갱신하고 수식 재설계는 별도 작업으로 다룹니다.
